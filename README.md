# UTM checker

Подсчет строк по `utm_campaign`: сначала из отдельного столбца «UTM Campaign»,
при отсутствии значения из «Комментарий» / «Комментарии», затем из явно
указанной метки `utm_campaign:` / `utm_campaign=` в остальных полях строки.
Результат текстом. Поддерживаются XLSX, XLS и HTML-экспорт Bitrix под расширением XLS.

## Локальная проверка

```powershell
python -m pip install -r requirements.txt
python checker.py "example.xls"
python -m unittest -v
```

Одна непустая строка после заголовка = один лид. Обрабатываются все листы со столбцом
UTM Campaign или комментариев. Названия кампаний сохраняют регистр. Повтор одной метки внутри строки
считается один раз. Строки с несколькими разными кампаниями и строки без метки
показываются отдельно. Дедупликации по телефону или ID нет.
Каждая строка учитывается один раз. Если в приоритетном источнике найдены несколько
разных кампаний, строка отмечается неоднозначной, значение из другого поля не подменяется.

Входной файл не изменяется. Результат не содержит телефоны и комментарии.
Пустые строки и повторные заголовки пропускаются.

В конце отчёта автоматически добавляется сумма лидов по кампаниям, начинающимся
с «Айкол», «Айколь», «Aikol», «Арча», «Archa» (без учёта регистра), пересечения
и разбивка остальных кампаний. После названия проекта должна идти граница слова
или разделитель: `Aikol_sale` учитывается, `Aikology` — нет.
Кампании `enesai_as_archa_*` остаются в остальных, поскольку не начинаются с Archa.
Строки без кампании и с неоднозначными значениями включены в «Остальные» отдельными
строками. Проверяется равенство общей суммы всех групп числу лидов.

## Telegram

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Заполнить BOT_TOKEN и ALLOWED_USER_IDS в .env (пример: .env.example).
.\.venv\Scripts\python.exe bot.py
```

Доступ проверяется по числовому Telegram user ID и только в личных чатах.
При пустом ALLOWED_USER_IDS доступ закрыт всем. После изменения списка перезапусти бота.
Результат приходит текстом, длинный отчет делится на сообщения. Входные файлы
обрабатываются в памяти, не сохраняются на диск. Токен хранится только в .env,
который исключен из git. Локальный процесс работает, пока компьютер включен.

На Linux-сервере: установить зависимости в venv, передать .env и запускать
`python bot.py` через systemd или Docker. Нужен один экземпляр polling-процесса.
Не запускай локальную и серверную копии одновременно с одним токеном.
